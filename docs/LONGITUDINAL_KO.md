# 종단 처방자료 처리 규칙 v1.0

이 기능은 CSV의 날짜별 처방에서 기준일의 **처방 기록상 추정 용량**을 산출한다. 실제 복용·투약을 확인한 값이 아니다. 원본 파일은 변경하지 않는다. 이 경로는 AI 호출, 피드백 수집, DB 저장을 하지 않는다.

## 입력과 기준일

- 피험자 ID, 처방일, 약물명(성분·단위 함량·제형), 하루 정/캡슐 수, 처방일수가 필수다. 제품명은 선택이며 있으면 교차 확인한다.
- SNU 열 `HID,PRESCR_DATE,DRUG,COMMERCIAL_DRUG,TABS_PER_DAY,PRESCR_DAYS` 및 한국어·영어 별칭을 자동 인식한다. 중복 후보 열은 사용자가 지정한다. 대소문자·공백·밑줄을 정규화한다.
- 일일 투여량이 정/캡슐 수라는 확인이 필요하다. 총 수량·1회 수량·mg/day는 이 모드에 직접 연결하지 않는다.
- 날짜는 YYYY-MM-DD, YYYY/MM/DD, YYYY.MM.DD, YYYYMMDD를 지원한다. 모호한 월/일 순서나 시각은 자동 추정하지 않는다.
- 처방일을 시작일로 간주한다. 적용 구간은 **시작일 이상, 시작일+처방일수 미만**이다. 원본/조정 종료일은 마지막 포함 날짜로 내보낸다.
- 공통 기준일, `patient_id,reference_date` CSV, 피험자별 모든 처방일을 지원한다. 모든 처방일 결과는 MRI·baseline 결과가 아니다. 실제 검사일을 제공해야 해당 분석이 가능하다.

## 중첩 정책

1. 기본 `review`: 같은 성분의 처방기간이 겹치면 중첩 기간의 합계를 빈칸으로 남긴다. 같은 용량 반복도 조기 재처방인지 확인할 수 없어 자동 병합하지 않는다.
2. 선택 `replace`: 같은 성분·경구 제형(IR/ER)의 확인 가능한 단일 처방은 다음 처방일부터 대체된다고 가정한다. 이전 종료일을 다음 처방일 전날로 자른다. 휴약 구간은 채우지 않고 잔여약을 이월하지 않는다. 새 처방 종료 후 이전 처방이 다시 살아나지 않는다. 결과는 `calculated_assumption`이다.
3. 같은 날 여러 행은 다른 함량 합산, 분할 복용, 중복 여부를 알 수 없으므로 검토 대상으로 유지한다. 완전 동일 행도 임의 삭제하지 않고 원본 행과 duplicate_of를 기록한다.
4. 다른 성분은 기간이 겹쳐도 별도 약물로 유지한다. 약물 교체·교차 감량은 추정하지 않는다.
5. 주사제·필요시·변동 복용·액제, 미확인 약물, 제품과 성분 필드의 함량·성분·서방 여부 충돌은 자동 환산하지 않는다. 처방일수를 주사 간격으로 사용하지 않는다.
6. 0·음수·소수 처방일수, 3,660일 초과, 비유한 값은 검토 대상으로 남긴다. 하루 100정 초과도 검토 대상이다. 이 범위는 임상적 허용량이 아니라 데이터 오류 검토 기준이다.
7. 날짜가 없는 미확정 약물은 그 피험자의 모든 기준일을 막는다. 일수가 없는 약물은 처방일부터 다음 동일 성분·제형 처방 전까지(없으면 이후 전체) 검토 대상이다. 이는 실제 복용기간의 추정이 아니라 누락된 정보를 합계에서 숨기지 않기 위한 보수적 처리다.
8. ID 누락 행은 어떤 피험자에도 임의 귀속하지 않고 Review에 남긴다. 해당 행이 누구 것인지 해결하기 전 파일 전체의 완전성을 보장하지 않는다.

## 환산과 결과

경구 고형제는 단위 함량(mg/정 또는 mg/캡슐) × 일일 정/캡슐 수로 mg/day를 계산한다. 기존 환산표를 그대로 사용하고 방법별 기준약물과 결과를 분리한다. 미확인 항목 또는 해당 환산법 계수 누락이 하나라도 있으면 해당 방법의 합계는 빈칸이다. 이름의 유사도 후보는 자동 채택하지 않는다. 명시적 비항정신병 성분 목록만 제외하며 미등록 이름은 검토 대상으로 둔다.

- Results.csv: 피험자·기준일·방법별 합계. `no_record`는 자료에서 해당 처방을 확인하지 못했다는 뜻이며 0이나 비복용이 아니다.
- MedicationResults.csv: 선택/차단된 원본 행, 일일용량, 방법별 결과, 기준일에 발생한 중첩 등 사유.
- Audit.csv: 모든 비어 있지 않은 원본 행의 처리 내역. 행 번호는 헤더를 1행으로 센 CSV 레코드 번호다. 셀 안 줄바꿈은 별도 행으로 세지 않는다.
- Review.csv: 행 자체의 검토 사유. 기준일별 중첩은 MedicationResults.csv에서 확인한다.
- Settings.json: 입력 파일 SHA256, 열 연결, 정책, 기준일 모드, 규칙 버전, 앱/환산표 버전.

검토 코드: `overlapping_orders` 처방기간 중첩; `same_day_multiple_orders` 같은 날 여러 처방; `duplicate_candidate` 동일 행 반복; `invalid_date` 날짜 확인; `invalid_days` 일수 확인; `invalid_daily_tablets` 일일 정 수 확인; `missing_patient` ID 누락; `unknown_drug` 미확인 약물; `ingredient_conflict` 성분 불일치; `strength_conflict` 함량 불일치; `strength_missing` 함량 누락; `product_strength_missing` 제품 함량 확인; `release_form_conflict` 서방 여부 불일치; `oral_solid_unconfirmed` 고형 경구제 확인; `injection_requires_review` 주사제 별도 확인; `variable_schedule` 변동 복용; `missing_factor` 환산 계수 없음.

## 검증 및 데이터 확인

중단·취소·처방번호·실제 투약 시작일이 없는 자료에서는 대체 정책을 사실로 확정할 수 없다. 전산실 정의를 확인하고 기본 review와 replace 결과 차이를 검토한다. 개인정보 원본 및 결과를 Git에 추가하지 않는다. 합성 자료로 웹/배포 검증하며 실제 자료는 로컬에서만 처리한다.

참고: [OMOP CDM v5.4 DRUG_EXPOSURE](https://ohdsi.github.io/CommonDataModel/cdm54.html#drug_exposure)는 처방·조제·투약 기록의 출처를 구분하고 시작일과 기간을 이용한 종료일 추정을 설명한다. 이 앱의 대체 정책은 해당 자료의 사실을 입증하는 표준 규칙이 아니라 사용자가 선택하는 분석 가정이다.
